| 10080 | Auth: refresh-token rotation must survive an app killed mid-refresh (persist before use; reuse-grace idempotency) | todo | | | | | Found 2026-10-11 while driving a real Roku. A client killed between the server rotating its refresh token and the client persisting the new one presents the retired token on the next start; beyond the 120 s reuse grace (`playarr-auth/src/refresh.rs`) the family is revoked and the device is signed out. Not reproduced for web logins: a fresh-device login and a login reusing another device id both left the Roku signed in; the store keeps one family per device id, revokes only on reuse detection or account deletion, and has no per-user session cap. Two hardening options. Client: write the new token pair to storage atomically before using it, and retry the refresh with the old token if the write did not happen. Server: inside the grace window return the same rotated pair for a retried old token (idempotent rotation) instead of rotating again or revoking. Applies to every client that refreshes at start-up. |
